CASE STUDY 01

How did I design a security feature that achieved an 85% enterprise adoption rate, a 40% reduction in support tickets, and a 30% decrease in misconfigured deployments?


Role

Senior Product Designer

Team

2 Engineering teams(Core & UI), PM, QA, Documentation team

Impact

85% enterprise adoption rate, 40% reduction in support tickets, 30% decrease in misconfigured deployments

Tools

Figma, Carbon Design System, Dovetail, Mixpanel

Project Context

This project aimed to implement the "Bring Your Own Encryption Key" (BYOEK) functionality, which allows enterprise customers to maintain control of their encryption keys while using our platform services.

The Problem

Business Challenge

Enterprise security requirements were hindering significant sales opportunities. Potential customers needed customer-managed encryption keys (BYOEK) to close deals, but our platform lacked a native solution.

Key Issues Identified:

  • No customer-managed encryption option for at-rest data
  • Existing encryption solutions had minimal visibility and control
  • Risk that implementing encryption functionality would add complexity and reduce conversion

Research & Discovery

I led a comprehensive discovery process to understand enterprise security requirements, competitive landscape, and technical constraints before defining the solution approach.

Competitive Analysis & Benchmarking

Analyzed encryption functionality implementations from AWS, Azure, Google Cloud, and other enterprise SaaS platforms. Documented their information architecture, workflow design, configuration complexity, and user feedback patterns.

Competitive analysis of encryption implementations across leading cloud platforms.

User Interviews & Workflow Mapping

I conducted 6 interviews with target customers already in sales conversations who required BYOEK. Focused on understanding: their current key management workflows, technical setup capabilities, migration concerns, and monitoring expectations.

User workflow mapping from interviews with enterprise customers requiring BYOEK functionality.

Key Insights from Research

The project had several challenges. First, users needed to trust the system and see the status of their encryption, key management, and data moving process. Second, setting up the encryption was too technical for people like compliance officers because it needed specific configuration (like JSON and KMS deployment). Third, different people needed different information: IT teams needed technical details, executives needed a simple status update, and security teams needed audit logs. Also, users were very worried about losing data when moving from the old encryption system to the new BYOEK system. Finally, the encryption needed constant checking and monitoring, not just a one-time setup, and enterprise customers wanted good support for setup but self-service tools for daily monitoring. I learned that a successful BYOEK solution needs more than just technical features. The most important things were to make the system easy to trust by showing users the status of their encryption, and to make the setup simple because non-technical people need to use it.

The Design Process

Information Architecture & System Design

Defined how encryption functionality would integrate into existing product ecosystem. Made critical architectural decisions about entry points, agent registration flows, data migration paths, and system monitoring placement.

Key architectural improvements and system design considerations for BYOEK integration.


Guided Configuration Wizard

Encryption functionality setup required customers to configure it via JSON files, intimidating for non-technical users.

I designed a step-by-step wizard with clear validation, examples, and warnings at each stage. Created detailed configuration guides integrated directly into the product documentation platform.

Progressive Disclosure

Broke complex setup into manageable steps with clear indicators

Inline Validation

Real-time feedback on configuration errors with specific remediation guidance

Example Templates

Pre-populated JSON configuration templates reducing manual coding errors


Transparent Status

Users needed continuous visibility into KMA health, encryption status and potential issues, but our design system lacked patterns for technical system monitoring.

I created reusable UI patterns: alert banners, connection state indicators, and diagnostic log screen. Built these as exportable components for future use across products.

  • Encryption coverage metrics showing which datasets were BYOEK-protected
  • Alert system for configuration issues, connection failures, or key access problems
  • Diagnostic logs accessible to technical users for troubleshooting

Design specifications for BYOEK monitoring and status indicators.

Prototyping & Validation

I created interactive Figma prototypes and conducted usability testing with 5 target customers. Tested configuration flow and dashboard comprehension

Interactive prototype framework for BYOEK configuration and validation flows.

Final design

The final design included a comprehensive BYOEK setup wizard, a transparent status dashboard, and reusable design system components for technical monitoring.

Initial plan was to make encryption functionality available to all customers, but this would have complicated the UX for users who didn't need it. I proposed restricting encryption functionality to Enterprise/Premium tiers. This allowed us to optimize the core platform for simplicity while providing sophisticated features where needed.

Final BYOEK prototype featuring comprehensive setup wizard and status dashboard.

Results & Impact

The BYOEK implementation exceeded adoption targets and became a critical differentiator in enterprise sales:

85% Enterprise Adoption Rate (3 months)

Within three months of launch, 85% of eligible enterprise customers activated encryption functionality—far exceeding internal projections and validating strong market demand.

40%

Reduction in support tickets related to configuration post-dashboard launch

30%

Decrease in misconfigured deployments through validation and examples

Reflection

This project taught critical lessons about balancing enterprise security requirements with user experience and managing complex stakeholder alignment.

I realized that for security features, transparency is key to building customer trust, which is vital for closing big Enterprise deals. We understood that users must feel confident and in control; giving them clear status indicators was as important as the technology itself. This confidence helps reduce support needs. Furthermore, we learned the value of making strategic trade-offs; by limiting complex features only to the Enterprise tier, we ensured the core platform remained simple and fast for most users while still meeting the needs of our most valuable customers. Finally, testing the product early with decision-makers was a great business choice, as it helped us avoid months of costly rework after the launch.
